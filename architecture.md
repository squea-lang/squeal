# Squeal — компилятор: архитектура

Две части: правила языка — отображение squeal на Erlang, и устройство компилятора (пайплайн `.ee` → `.beam`).

## Правила языка

### Имена и модули

- Модуль — это путь файла под `src/`: `src/a/b/c.ee` → Erlang-модуль `a@b@c` (разделитель `@`, как у Gleam).
- `from a.b.c import f` → вызов `a@b@c:f(...)`; `from a.b.c import f, g as h` — несколько имён и псевдоним (`h` → `a@b@c:g`); `import *` и `import X` — ошибка.
- Переменные маппятся как у Gleam: первое связывание имени — `X`, каждое следующее переприсваивание — `X@1`, `X@2`… (`x = x + 1` → `X@1 = X + 1`). Внутренние временные переменные — `_squeal@0`, `_squeal@1`… (`@` в Python-идентификаторе нет, поэтому коллизий с переменными пользователя не бывает).

### Значения

- Строка `"..."` (двойные кавычки) → бинарник `<<"..."/utf8>>`; атом `'ok'` (одинарные кавычки) → атом — кавычки различают строку и атом.
- `True`/`False` → `true`/`false`; `None` → `nil`; `int`/`float` → Erlang number.
- кортеж `(a, b)` → `{a, b}`; список `[a, b]` → `[a, b]`; словарь `{'k': v}` → `#{k => v}` (атом-ключ), `{"k": v}` → `#{"k" => v}` (бинарный ключ).

### Операторы

- `+ - * < <= > >=` — как у Gleam (те же формы); `!=` → `/=`.
- `==` → Erlang `==` (коэрцирующее, `1 == 1.0` true — Python-семантика); `is`/`is not` — ошибка компиляции.
- `and`/`or`/`not` → `andalso`/`orelse`/`not`, операнды только bool (иное — `badarg`).
- `// % **` — Python-семантика: `//` floor (`(A − Mod) div B`), `%` modulo со знаком делителя (`(A rem B + B) rem B`), `**` — целочисленное возведение при int**int(≥0), иначе `math:pow`. Операнды связываются в свежие `_squeal@N`-переменные; на ноль — падение (`badarith`).
- `/` — сырое Erlang `/` (float-деление; на ноль — `badarith`).

### Классы-типы

- `class T(StartingWithAtom): x: int` — аннотации только документация; класс в рантайм не эмитится. Конструктор `T(…)` **инлайнится** в кортеж `{t, …}` (тег — имя класса в snake_case, как у Gleam; функции-конструктора нет); число аргументов конструктора и образца `case T(x):` проверяется против числа полей.
- `class R(NativeRecord)` и `class M(Map)` — нативный рекорд OTP29 и map; точное отображение не подтверждено (пока — ошибка компиляции).

### Неизменяемость и присваивание

- `for`, `while`, `del`, `+= -= *= /=` и присваивание по индексу/атрибуту — ошибка компиляции (см. Проверки).
- Переприсваивание имени разрешено: новое Erlang-имя по схеме `X@N` (параметр — первая привязка `X`). Неопределённое имя — ошибка компиляции.
- `head, *rest = my_list` → образец-список `[Head | Rest]`; `a, b = t` → образец-кортеж `{A, B}` (паритет с Gleam); несовпадение — `badmatch` (let it crash).
- `my_map |= {'k': v}` → `maps:merge(M, D)`; не-map — `badmap` (let it crash).

### Ветвления

- `if c: a else: b` → `case C of true -> A; false -> B end`: истинно только `true`; любое другое значение роняет процесс (`case_clause`) — «let it crash».
- `match v: case p1: … case p2: …` → `case V of … end` без fallthrough: ни один образец не совпал — рантайм падает с `{case_clause, V}`.
- `case 1 | 2:` → по клаузе на каждый образец с общим телом (or-образец не связывает переменные); `case p if cond:` → `when Cond`.
- Захват `case name:` связывает значение (как Python/Gleam); `_` — wildcard. Последовательности: `case [h, *rest]:` — список, `case (a, b):` — кортеж (различаются по скобкам).
- Переменные, связанные внутри ветки, не утекают наружу (scope ветки); `if` без `else` — ошибка компиляции.
- Каждая ветка `if`/`match` заканчивается присваиванием одной и той же переменной (проверка компилятора) — ветки генерируются как выражение `case`, и его значение присваивается этой переменной.
- `_` — wildcard; образцы — литералы, классы, списки/кортежи/словари — как в Python.

### Функции, лямбды, включения

- `def f(a, b): …` → `f(A, B) -> …`; значение функции — последний оператор тела (присваивание — тоже значение). Экспортируются все функции модуля.
- `lambda x: e` → `fun(X) -> E end`; замыкание захватывает значение (как у Gleam), а не позднюю привязку Python: переприсваивание имени после лямбды не меняет уже захваченное значение.
- `[e for x in l if c]` → `[E || X <- L, C]`; `{k: v for …}` → map comprehension (OTP 26+). Генераторы, фильтры и вложенность переносятся 1:1 в том же порядке; образец-цель генератора пропускает несовпавшие элементы — как в Python, так и в Erlang. Фильтр — `true` сохраняет, иное пропускает (семантика Erlang; в отличие от `if`, который падает). Множеств в squeal нет → set comprehension — ошибка компиляции.
- Итерация словаря: `for k in m` → `K <- squeal_iter(M)` — map даёт ключи, список даёт элементы, иное — `bad_generator` (let it crash). Все генераторы list/dict-включений идут через `squeal_iter` (единая семантика: словарь → ключи, список → элементы). Пары — явно: `for k, v in m.items()` → map-генератор `K := V <- M` (без `maps:to_list`; не-map — `bad_generator`).
- **Методы** — whitelist в компиляторе: имя метода сверяется с таблицей известных, неизвестное — ошибка компиляции. В первой сборке единственный метод — `.items()`. **Правило языка, а не проверка:** считается, что `.items()` вызывается только у словаря — видим метод, значит получатель словарь; компилятор сверяет с whitelist-таблицей только имя метода (неизвестное — ошибка компиляции), нарушение правила ловит рантайм: map-генератор `K := V <- M` на не-словаре — `bad_generator`, выражение `maps:to_list(M)` — `badmap` (let it crash). Таблица пополняется методами типов стандартной библиотеки.

## Компилятор

```
src/a/b.ee ──ast.parse──▶ Python AST ──▶ IR ──▶ проверки ──▶ abstract forms ──compile:forms──▶ .beam
```

- **Фронтенд** — стоковый `ast.parse` из CPython 3.15. Разбор и позиции достаются бесплатно; `compile()` не вызывается, чтобы питоновские проверки не мешали нашей семантике.
- **IR** — собственное представление (структуры с номером строки `.ee`). Соответствует слою `TypedExpr`/`TypedModule` у Gleam (`compiler-core/src/ast/typed.rs` — дерево, которое обходит генератор кода), но **без типов**: место инференса занимают проверки. Это безопасно для паритета: генератор Erlang у Gleam выведенные типы почти не читает (только при печати `-spec`), форму кода выбирает вариант узла — то есть синтаксис. Поэтому squeal не кладёт в формы типовую информацию: аннотации остаются документацией, `-spec`/`-type` не генерируются. Набор узлов — по категориям `TypedExpr`, чтобы обход бэкенда повторял генератор Gleam. Фронтенд за IR не виден: когда появится синтаксис сверх Python, заменится только фронтенд, бэкенд не тронется.
- **Проверки** — разделены: фронтенд отклоняет запрещённый синтаксис (`for`/`while`/`del`/мутация, whitelist узлов), бэкенд проверяет «ветка заканчивается присваиванием той же переменной», `checks.py` — дубли определений.
- **Бэкенд** — как `erlang-generation` у Gleam 1.19: builder поверх Erlang Abstract Format, каждая форма несёт аннотацию строки `.ee`, поэтому stack traces указывают в исходник squeal. Формы печатаются как Erlang-термы в файл `.abstr`. Атрибут `compile` повторяет Gleam (`no_auto_import, nowarn_ignored, nowarn_unused_vars, nowarn_unused_function, nowarn_nomatch, inline`).
- **Сборка** — escript читает `.abstr` (ASCII; строки экранируются `\x{HEX}`) и зовёт `compile:forms` с `[return, report_errors, report_warnings, debug_info, {source, Path}]`; `.beam` кладётся в ebin, рядом генерируется `<app>.app`, `.erl` для отладки — `erl_pp` тех же форм.

Соответствие с Gleam обязательно только на нижнем слое — abstract format: builder повторяет `erlang-generation`, для одинаковых синтаксических узлов squeal строит те же формы, что Gleam; выше (Python AST, IR) — свои слои.

## Командная строка

`python -m squeal build [DIR]` — подкоманды как у Gleam; первая сборка знает только `build`. Компилирует дерево `src/` в `build/dev/erlang/<app>/ebin`, `<app>` — имя каталога проекта; артефакты `.abstr` — в `build/dev/erlang/<app>/_squeal_artefacts`.

## Jupyter

Ноутбук без кастомного kernel: ячейка остаётся Python-текстом (автокомплит/линт даёт Python-LSP),
а выполнение перехватывает ipykernel-хук `squeal.notebook`: `ast_transformer` подменяет тело на
`pass`, `post_run_cell` компилирует исходник в shell-режиме и исполняет в persistent Erlang-REPL.

- **Shell-режим** (`session.py`): клетка → Erlang-выражения (не модуль); `def` → именованный fun
  `F = fun F(X) -> … end` (рекурсия работает); `_taken`/`_scope`/классы/импорты живут в session
  (маппинг `X@N` продолжается через ячейки). Повторный запуск клетки безопасен: классы
  переопределяются, переприсваивание даёт новое имя `X@N`.
- **REPL** (`repl.py` + `repl.escript`): persistent процесс, `erl_eval:exprs` принимает формы
  напрямую, bindings живут между ячейками; вывод — результат последнего выражения (определения
  вывод не дают). Хелперы `_squeal_pow`/`squeal_iter` предзаданы в REPL как fun-значения, и
  shell-режим зовёт их по переменной (в модульной сборке — локальные функции).

## Паритет с Gleam

- Требование goal doc — одинаковый сгенерированный код. Механизм: установленный `gleam` 1.19.2 (тот же, что вендорен в `gleam/`) компилирует эквивалентный `.gleam`-модуль; beam несёт abstract code (`debug_info`), формы достаются `beam_lib:chunks(Beam, [abstract_code])` и сравниваются с формами squeal после нормализации аннотаций строк.
- 10–20 таких тестов (pytest); один тест — пара эквивалентных модулей squeal/gleam.
- Пары есть не у всех конструкций: `|=`-слияние, `.items()`, неисчерпываемый match и включения не имеют аналога в Gleam — их поведение проверяется обычными тестами.
- Пары на match — только исчерпываемые: Gleam добавляет fallthrough-клаузу, которой у squeal нет по дизайну.
