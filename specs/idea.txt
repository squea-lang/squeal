я собираюсь сделать gleam с питоновским синтаксисом, назвать его squeal. Расширение файлов .ee

**Идея**

для статического анализа использовать форкнутый статический анализатор для питона (например, на Kotlin, для пайчарм)
для компиляции кода использовать питоновский пакет и питоновский парсер. Это - потому что синтаксис squeal совпадает с синтаксисом питона. Со временем, будем поддерживать дополнительный синтаксис, кроме питоновского (паттерн матчинг, пайплайны). Но пока (milestone 1) - чистый питоновский.

**Без мутирующих операций**

синтаксис - питоновский, из которого выкидываем мутирующие операции. Например, выкидываем циклы for.
Переменная может быть присвоена заново: x = x + 1. Маппинг имен переменных на эрланговские - такой же, как в gleam.

Например, работа со списками и словарями:

head, *rest = my_list
my_map |= {'key': 'value'}

**импорты** иерархические, синтаксис для них питоновский

from my.custom.pak import my_fun

Так же сделано и в gleam.

**if, case**

со временем будет так:

value =
  if condition:
    a
  else:
    b

val = match expr:
  case expr1:
    do_first()
  case expr2:
    do_second()

Но пока используем питоновский синтаксис:

if condition:
  value = a
else:
  value = b

match expr:
  case expr1:
    val = do_first()
  case expr2:
    val = do_second()

Компилятор проверяет, что последняя операция - присваивание и что присваивается одна и та же переменная

**Let it crash**

Это касается оператора match. Один из вариантов должен сматчится - иначе ошибка в рантайме и крэш процесса. Этим squeal отличается от gleam, где компилятор не скомпилирует этот код и заставит перечислить все варианты в case.


**Паттерн матчинг**

Пока - через match..case. В дальней перспективе - let MyPattern = Expr

**атомы**

через одинарные кавычки 'ok'

Вместо атомов рекомендуется использовать типы - так же, как в gleam.Они определяются примерно так (все названия - чтобы объяснить схему)

class CustomType(StartingWithAtom):
  x: int
  y: int

match val:
  case CustomType(x, y):
    result = (x, y)

это эквивалентно

match val:
  case ('custom_type', x, y):
    result = (x, y)

Кроме этого, могут быть такие типы (тоже - для схемы)

class CustomRecord(NativeRecord):
  x: int
  y: int

NativeRecord - нативный рекорд из OTP29, который не теряет свой тип в рантайме

class CustomMap(Map):
  x: int
  y: int


**Язык реализации**

Это питон. В перспективы, некоторые части планируется реализовать на spy (static python).

Важно: Хотя пока не планируется переиспользовать код из Gleam, абстракции должны использоваться те же. По крайней - мере, абстракция на самом нижнем уровне, который генерирует абстрактный эрланг. И код для разных синтаксических узлов должен генерироваться такой же. Код должен генерироваться в Abstract Erlang Forms, также как в gleam.
