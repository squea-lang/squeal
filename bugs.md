Критичное
Компилятор падает с traceback на пустых ветках — if c: pass / else: ... и case 1: pass → IndexError в _branch_body (backend.py:266, stmts[-1] на пустом кортеже) вместо SquealError.
Голый return → AttributeError: 'NoneType' object has no attribute 'lineno' (frontend.py:378) — SquealError даже неthrown.
Любая ошибка erlc (например, локальный вызов неверной арности) → CalledProcessError traceback (compiler.py:56 check=True), а SPEC.md:20 обещает «без traceback», формат squeal: путь:строка:. Модуль-режим не проверяет имена/арность вообще (нет _later_defs-аналога) — арность ловится только эрлаком.
Декораторы молча выбрасываются: @dec\ndef g() компилируется как обычная функция. Молчаливая порча программы — хуже краша; нужен SquealError в _function.
Коллизия имён хелперов: def squeal_iter(x) в модульном режиме → дубликат squeal_iter/1 → erlc-ошибка; в shell-режиме вызовы включений идут в lowercase-хелпер, пользовательский смысла не вызывается никогда (maps:keys на списке → badmap).
Мажорное
Функции не значения (регрессия коммита арности): g = f → «имя f не определено» в shell, а в модульном топ-левел функции вообще нельзя передавать как аргумент (нет fun f/1); паритет-тест покрывает только лямбды.
%/// на float → badarith (-7.5 % 2 в Python = 0.5) — README обещает Python-семантику.
Ошибка имени без строки (src/m.ee:имя 'b' не определено, backend.py:130) — нарушает заявленный формат.
Notebook: импорты постоянны нерабочие — REPL запускается без -pa, from mod import f даёт {error,undef}; не покрыто тестами.
unload_ipython_extension — заглушка: повторная загрузка дублирует хуки, ErlangRepl — зомби-процесс.
case 1 не матчит 1.0 (=:= в паттернах), а Python-матч матчит — расхождение не задокументировано.
Теги классов ориентируются только по snake_case: CustomType и Custom_type — один рантайм-тег, проверки нет.
